# APT 芯片通用硬件约束

> 以下约束**适用于所有 APT32 系列芯片**(不限于某个型号)，迁移任何模块时必须遵守。

## 外设寄存器不可 byte/half-word 寻址（仅限寄存器空间，SRAM 无此问题）

**仅外设控制寄存器**不支持 byte 或 half-word 寻址(CRC DATAIN 除外)。
寄存器为 32-bit 宽，CPU 必须以**32-bit 字**为单位读-改-写。
**SRAM 无此限制**——普通变量、数组、位域在 SRAM 里 byte/half-word 访问完全正常。

### 典型事故场景：C 位域映射到寄存器地址→半字失效

从 8051 迁移时，工程师可能用 C 位域(bit-field)结构体映射寄存器，试图模拟 8051 的 `sbit` 操作：

```c
typedef struct {
    uint16_t bit0 : 1;
    // ...
    uint16_t bit15 : 1;
} Bits_16_TypeDef;
```

**现象**：bit0~bit7 能正常输出高低，bit8~bit15 **始终为低**、无法输出。

**原因**：编译器将位域结构体当作 16-bit 半字处理 → 生成半字 load/store 指令 → APT 总线不支持半字写入寄存器 → 高字节(bit8-15)写不进去。

**bit0-7 碰巧能工作**，反而让问题更隐蔽——看起来"部分能用"，实际是硬件未正确处理半字访问的侥幸结果。

### 禁止的操作

- 直接赋值寄存器：`GPIOB0->SODR = 0x01`(可能扩展为未知 32-bit 值)
- **位域结构体映射寄存器**(上面那种)——从 8051 迁移最爱犯
- byte/半字指针强转：`*(uint8_t*)&REG = 0xFF`

### 正确做法

**一律通过 APT 驱动 API 函数操作寄存器**，API 内部正确处理了 32-bit 读-改-写：
- GPIO：`gpio_set_high/low()`、`gpio_reverse()`、`gpio_configure()`
- 定时器：`bt_set_prdr_cmp()`、`bt_configure()`
- ADC：`adc_get_data()`、`adc_ain_configure()`
- ……

### 迁移时怎么识别这个坑

检查源代码中是否有：
- 位域结构体访问寄存器地址
- 非 32-bit 的指针强转指向外设地址
- `#define PIN_NAME  ((Bits_TypeDef*)&REG)->bitx` 之类宏

**发现一律不允许——需改成 APT 驱动函数调用。**
编译不报错，行为诡异，且部分 bit 能工作更迷惑人——是 8→32 bit 迁移最隐蔽的 bug。
