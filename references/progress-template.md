# 移植进度文件模板 (PORTING_PROGRESS.md)

在**客户工程目录**维护此文件。每步更新，会话开始先读。
它有双重作用：① 进度存档(跨会话/跨天/换 AI 都能续) ② 核对客户改动的基准(原则9)。

复制下面结构，随迁移填写：

```markdown
# 移植进度：<源芯片> → <目标APT型号>

## 关键上下文(供后续模块引用)
- 目标主频：<如 48MHz>；源主频：<如 12MHz>；比值：<如 4×>
- 调试打印：<硬件UART0@PA05,256000 / 半主机>
- 源芯片寄存器定义：<路径，如 BF7612CMXX.h / xxx.svd>
- 工具链/编译：<路径、make 命令>

## 模块清单与状态
| 模块 | 状态 | 涉及文件 | 备注/文件基准 |
|---|---|---|---|
| 白纸骨架 | ✅客户已验证 | main/initial/interrupt/iostring | heartbeat 正常 |
| 时钟 | ✅客户已验证 | initial.c | 用demo配置,48MHz |
| GPIO | 迁移中 | io适配层 | 等客户测 PB0 |
| 定时器 | 未开始 | - | - |
| ... | | | |

状态取值：未开始 / 迁移中 / 编译过(未上板) / ✅客户已验证 / 有客户改动待确认

## 新增/改动的文件(基准，供核对客户改动)
- 新增 `xxx.c`：已注册 mk + cdkproj
- 改动 `initial.c`：console 引脚改 PA05
- (每次留给客户测之前，在此记下当前状态)

## 待确认问题(需客户/FAE 决策)
- [ ] ADC 通道：源"通道24"对应 APT 哪个物理引脚？
- [ ] 某外设 APT 无对应，替代方案待定
- [ ] (发现"中断触发另一模块"→ 记此，标注 ETCB 可优化)

## 变更日志(可选)
- <日期> 完成 X，客户验证通过
```

## 使用要点
- **每完成一步就更新**，不要攒着。
- **每个模块调试结束，用进度条+清单格式报给客户**，格式如下：
  ```
  [████████░░░░░░░░░░░░] 3/12 (25%)
  ✅ 白纸骨架  ✅ 时钟  ✅ GPIO
  ⬜ 定时器  ⬜ ADC  ⬜ EEPROM  ⬜ 显示  ⬜ 触摸  ⬜ 蜂鸣  ⬜ 门检测  ⬜ 加热  ⬜ 业务
  下一个：定时器
  ```
  `█` = 已完成, `░` = 待完成。进度条长度和模块除以总数成比例。
- 客户反馈后先用它当基准，核对客户有没有改动过工程(原则9)。
- 换会话/隔天继续时，**第一件事读它**，不要凭记忆假设进度和文件状态。
