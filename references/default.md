# APT 芯片迁移通用知识（默认加载，适用所有型号）

> 以下知识**不绑定特定芯片型号**，任何 APT32 系列迁移都必须遵守。
> 芯片特有信息（外设/API/引脚）见 `chips/<型号>.md`。

## 内核与命名

APT32 系列多为 T-Head（玄铁）**CK801** 内核。**T-Head 命名规则里 CK801 = E801**（CK 为旧称，E 为新称，同一内核）。
资料/工具里出现 E801 与 CK801 指的是同一个；编译参数用 `-mcpu=ck801`。

## 硬件约束

### 外设寄存器不可 byte/half-word 寻址（仅限寄存器空间，SRAM 无此问题）

**仅外设控制寄存器**不支持 byte 或 half-word 寻址(CRC DATAIN 除外)，必须 32-bit 字访问。
**SRAM 无此限制**——普通变量、数组、结构体位域放在 SRAM 里，byte/half-word 访问完全正常。

**典型事故：C 位域映射到寄存器地址导致半字失效**
从 8051 迁移时，可能用位域结构体映射**外设寄存器**来模拟 `sbit`：
```c
typedef struct { uint16_t bit0:1; ... uint16_t bit15:1; } Bits_16_TypeDef;
#define PIN_REG  ((Bits_16_TypeDef*)&GPIOx_SODR)  // ← 指到外设寄存器地址，有问题
PIN_REG->bit8 = 1;  // 编译器生成半字写 → APT 外设总线不支持 → 写不进去
```
现象：bit0~7 正常、bit8~15 始终为低。bit0-7 碰巧能工作，反让问题更隐蔽。
如果同一结构体定义用在 SRAM 里的普通变量上，完全没问题——**问题只在"指到了外设寄存器地址"**。

禁止：位域结构体/byte 指针/**非 32-bit 访问**指向**外设寄存器地址**。
正确：一律用 APT 驱动 API（`gpio_set_high()`、`bt_set_prdr_cmp()` 等）—— API 内做了正确字宽。

## 编译规则

1. **整工程编译**：必须 `make -f cdkws.mk`，不能只编单文件（单文件发现不了链接层问题）
2. **改后先 clean**：增量 .o 缓存会骗人，每次验证前 clean 再全量编
3. **新增 .c 文件**：必须同步改 `.mk`(AI 编译用) 和 `.cdkproj`(客户 CDK 重新生成用)，缺一则一方编不过
   - 改 cdkproj 后用 `cdk-make /w xxx.cdkws /c BuildSet /d build` 重新生成 mk
4. **不要用 cdk-make 做日常编译**（用 make），它只用于从 cdkproj 重新生成 mk

详见 `build.md`。

## 迁移铁律

1. **先底座后逻辑**：硬件模块逐一配好验证，全过后才引入纯C业务逻辑
2. **分步验证，不确认不前进**：每模块 = 改代码→编译 0 error→引导客户测→客户确认→下一模块
3. **物理量守恒**：带时钟模块不许抄源数值，按目标主频重算，保物理量(Hz/波特率/us)不变
4. **适配层保接口语义**：底座接口保持源工程函数/宏名，只换内部实现，业务代码零改动
5. **代码是事实，注释是传闻**：理解源码以寄存器操作+代码行为为准，注释仅参考
6. **客户可能并行改代码，绝不静默覆盖**：每次动工程前核对文件当前状态，发现客户改动先问
7. **维护并汇报进度**：每模块结束更新 `PORTING_PROGRESS.md` 并主动报给客户（整体进度 + 本模块结论 + 下一个）

详见 SKILL.md 和 `module-guide.md`。

## 工程结构原则

- **硬件适配集中在 `porting.c`**：所有适配层(宏/包装函数/定时器重算/寄存器操作翻译)放在 `porting.c`+`porting.h`。其余文件(`key.c`/`work.c`/`display.c`…)只放纯 C 业务逻辑,和源工程完全一致,通过 `porting.h` 调用硬件。
- **目录结构参照源工程**：源工程有什么子目录(如 `Project/`、`CTK_Library/`、`Application_Library/`),目标就建同样的子目录,文件放各自对应位置。每个子目录加入 IncludePath。
- **按源工程建文件**：源工程有哪些 `.c`,就建同名 `.c`+`.h`,一次性注册进 `.cdkproj`(`cdk-make` 自动生成 mk)。后面逐个模块填实现。
- **只注册 `.c`**：`.h` 靠 IncludePath,不需要在 cdkproj 里逐个加 `<File>`。

## 从 8051 迁移特别注意

- 8051 的 `sfr`/`sbit` 直接寄存器操作**不能照搬**（见硬件约束）
- `data`/`xdata`/`code`/`bit` 关键字 → 去掉或改为普通类型
- `interrupt N` ISR → 改为 APT 固定名 ISR(`CORETHandler` 等，见芯片能力清单)
- 引脚的源编号 ≠ APT 编号，按物理接线重新映射，**问客户**
- `do{}while(0)` 包裹多语句宏(8051 宏常有多语句)
