# LPT CNT值读出异常的解释

## 适用于所有APTCHIPs

有客户反馈LPT工作于one shot模式时，一个周期计数结束后，理论上LPT 应该停止计数，但是实际看到的CNT值既不是 0 也不是 PRDR 值，甚至都不是一个常数。
比如设置PRDR = 27000，那通过串口打印出来的CNT值可能是26998，26999，26997，27000\.\.\.



而这种现象只有在LPT的clock source选择ISOSC的时候才会出现。
此时，LPT内部存在两个时钟域

- 一个是作为clock source的ISOSC

- 一个是用来实现寄存器读写和更新的PCLK （大部分IP都挂在APH上，也有一些诸如memory、DMA、ADC、CRC、GPIO这种往往会挂在AHB上）

上图中的这种不确定性正是源自这两个时钟域的同步具有一定的随机性。


事实上，即使我们以超高主频去读取CNT寄存器，读到的也不是连续的值。因为更新并不在每个主频时钟周期发生。

所有内部存在两个时钟域的模块都可能出现这个现象。
