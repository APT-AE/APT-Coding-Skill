01 / 认识

什么是 APT Coding Skill？

⚠ 前提：你的 AI 工具必须能操作电脑上的文件和文件夹（读源码、改代码、命令行编译）。
Claude Code、CodeBuddy、Cursor 等可以；网页版 AI 不行，因为它无法操作你电脑里的文件。

通用的 SKILL.md 标准，支持所有主流 AI 编程工具。包含完整的芯片参考文档、FAQ、IP 对比表。

02 / 场景

四种支持场景

场景适用条件执行方式复杂度
Case 1
跨厂迁移		 源芯片不是 APT
8051 / ARM / RISC-V / PIC …		 需清理源特有语法 → 寄存器翻译 → 适配层 → 逐模块验证 ●●●
Case 2
同厂升级		 源芯片是 APT 旧型号 跳过语法清理 + 适配层 → 重点做新旧差异核对 ●○○
Case 3
从零开发		 无现成代码，只有需求 从 demo 起步 → 对照芯片能力清单 → 按需求直接实现 ●●○
Case 4
项目排错		 正在开发的 APT 项目遇到问题 AI 加载技能诊断 → 结合芯片手册定位 → 给出修复方案 ●○○

03 / 原则

基本执行原则

01 先底座后逻辑 — 硬件模块逐个配好验证，全通过后才引入纯 C 业务逻辑
02 物理量守恒 — 带时钟的模块（定时器/串口/ADC）不直接搬源芯片数值，而按目标主频重算
03 基于事实 — API/引脚/通道一律以实际驱动头文件和芯片能力清单为准，找不到先问客户
04 修改后确保编译通过 — 确保工程编译无错后才让客户烧录验证
05 分步确认 — 每个模块改完→编译→客户验证通过→推进下一个
